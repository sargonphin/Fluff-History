# M25 — Pre-Release Preparations

## Purpose and delivered behavior

Consolidated pre-release product polish, independent exclusions, encryption
maintenance, localization, packaging/version identity and automatic updates before
public repository preparation. This record summarizes the phase; current contracts
live in the linked topic documents rather than separate sub-milestone diaries.

## Important decisions

- Independent absolute excluded-folder choices project into existing relative
  source configuration; inactive/unmatched choices remain, explicit full-source
  conflicts reject in either edit direction. Directory exclusions do not suppress a
  future regular file at the exact name. Historical file/folder collision rows keep
  distinct navigation/selection identity.
- Recovery-password rotation changes only a same-master wrapper. Exclusive resumable
  encryption conversion fences older clients with an unsupported-mode sentinel,
  verifies payload/semantic continuity, installs target state first, authenticates
  Ready and commits the target bootstrap. Recovery preserves later target advancement.
- OneDrive superseded experimental PasswordVault recovery while retaining password
  and local DPAPI independence. Exact license/archive guards pin the reviewed WAM
  dependency set; the feature remains Experimental.
- Application artwork is reproducible from the retained composite. Native Windows
  resource icons are loaded from the OS, not copied as supposedly open-source assets.
  All pages share one PageLayout geometry. Titlebar and friendly process metadata
  distinguish management UI from the background Agent.
- Forty-four English-first catalogs feed live MRT/typed presentation, native Shell
  resources and 43 pinned-base installer languages. Diagnostic/machine contracts
  remain invariant; regional formatting and language are separate. Bulk catalog
  validation avoids pretending each translation has an installed visual campaign.
- Semantic stable/beta release identity is distinct from four-part PE/package
  identity. Agent-owned GitHub discovery, bounded verified staging and detached
  handoff preserve ordinary Setup replacement/rollback and repository independence.
  Production updater execution requires explicit signer approval.

## Validation performed

Focused/ordinary suites covered independent exclusions, file/directory replacement,
default sources, security UI, wrapper rotation, faulted/resumable conversion, older
released-client fencing, actual target advancement, status/maintenance, localization
guards and updater grammar/state/admission/staging. Installed campaigns exercised
representative Latin/RTL/CJK switching, Shell/Agent lifetime, package inventory,
conversion and controlled update rollback/busy/manual-cancellation paths. Bare-metal
and account failure matrices remain distinct from those successes.

Controlled update builds demonstrated automatic busy deferral with actual backup
completion, manual cancel-versus-confirm behavior, Setup rollback and preserved
settings/repository byte hashes. They did not approve the private test signer for
public releases. The normal development package 0.24.1.236 was installed for final
shared-layout checks; the later 0.24.1.238 correction was built, not separately installed.

The pre-merge retry correction confirmed persisted AutomaticPending could survive a
committed handoff/failed Setup and cause old-Agent retry. Seven regression cases
failed before the fix; the focused set then passed 102 tests. Pending now consumes
durably before handoff, re-arms only explicit Busy/BackupStillRunning, and missing
digest remains announcement-only. Manual retry is immediate; automatic retry waits
for a later ordinary scheduled check.

## Limits and current relationship

At the end of this phase, first-party licensing, vulnerability reporting, publisher
signing, distribution terms/Store policy and release automation remained unresolved.
Current licensing and release requirements are documented in the topic guides.
Windows-account provisioning research remains
historically unproven; OneDrive core A/B success does not complete wrong-account,
revocation/quota, real legacy migration or bare-metal checks. Framework captions,
installer base-message fallbacks, preview cleanup and blocked I/O remain disclosed.
